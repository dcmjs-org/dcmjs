(draft) dcmjs 1.0 is available

Steve Pieper, for the dcmjs community. December 2026.

The dcmjs project has published dcmjs 1.0. The release is on npm as @dcmjs-org/dcmjs. It follows twelve beta releases, which the main downstream projects used and tested.

What changed in 1.0

dcmjs 1.0 is a major rewrite of the library. The library is now a set of packages that you can install separately:

  • @dcmjs-org/core holds the shared building blocks.
  • @dcmjs-org/legacy keeps the readers and writers of 0.x.
  • @dcmjs-org/parser and @dcmjs-org/generator add a new streaming reader and writer that handle files larger than memory.
  • @dcmjs-org/schemas, dicomdir, encapsulated, imaging, video, media and fhir hold the specialized features.

The @dcmjs-org/dcmjs package re-exports the same names as dcmjs 0.52, so most projects change only the import line. The largest change is in naturalization: it no longer uses a Proxy, and the VM of the DICOM dictionary decides the shape of each value. A single-item sequence is now the item object, a VM 1-n attribute such as ImageType or WindowCenter stays a list even with one value, and private elements are grouped by their private creator block.

The release also has many fixes: private elements now survive a denaturalize and write, multi-valued ISO 2022 SpecificCharacterSet values decode, and cleanTags empties about 103 more attributes. A new frameDataset function gives a view of one frame of a multi-frame dataset. The migration guide and the list of breaking changes give the details.

From the beta to the release

The beta releases started in November 2026. During the beta, we moved the main downstream projects to dcmjs 1.0, found the places where the new naturalized shapes broke existing code, and fixed them. With the release, these projects move from a pin on a beta version to dcmjs 1.0. Please report problems as issues on dcmjs-org/dcmjs.

How dcmjs 1.0 is used today

Each pull request below also serves as an example of the migration, with a list of the changes that the new shapes needed.

Static-DICOMweb

  • RadicalImaging/Static-DICOMWeb#159: update dcmjs 0.52.0 to @dcmjs-org/dcmjs, through an npm alias, so that the import ... from 'dcmjs' lines do not change. The description lists each user-visible change, for example private elements on C-STORE that are now kept.

Cornerstone3D

  • cornerstonejs/cornerstone3D#3019: move the adapters, metadata and utils packages to dcmjs 1.0. The pull request fixes the SEG and SR readers for the new shapes, adds the helpers asMultiValueArray, getPrivateTagValue and findPrivateTag, and uses the dcmjs frameDataset for multi-frame instances.

OHIF Viewer

  • OHIF/Viewers#6397: move OHIF to dcmjs 1.0, together with the Cornerstone3D pull request above. The pull request fixes RTSTRUCT, SR, PET SUV, microscopy, bulk data and tag browser code for the new shapes.
  • Deploy preview, built with the Cornerstone3D branch and dcmjs 1.0: cs3d-pr-6397--ohif-dev.netlify.app.

dcmjs-commands

dcmjs-commands is a command-line toolkit and an MCP server (for AI agents) built on dcmjs 1.0.

  • dcmjs-org/dcmjs-commands#8: the modernized CLI on dcmjs 1.0, with streaming conversion, anonymization, validation, DICOMDIR and Static-DICOMweb output.
  • dcmjs-org/dcmjs-commands#9: dcmjs transcode changes the transfer syntax of Part 10 files one frame at a time, for example a lossless conversion of JPEG to JPEG XL. dcmjs wsiresize builds a new pyramid for a whole-slide image series with a new tile size and transfer syntax.
  • dcmjs-org/dcmjs-commands#11: dcmjs multiframe converts classic single-frame CT, MR and PET images to Legacy Converted Enhanced images, from Part 10 files or from a Static-DICOMweb tree.
