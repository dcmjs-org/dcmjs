Update — debt paid down (2026-08-03, PR #46 technical-debt-cleanup → development)

A focused paydown pass retired the highest-value structural debt and both medium engineering debts registered below, and changed which reader runs by default:

  • AD-1 (HIGH) — resolved: every reader now decides the same way whether an implicitly-encoded, defined-length element is actually a sequence. The two separate copies of that look-ahead check were removed in favor of a single one in the shared decode routine (b9dd8d7).
  • AD-5 (LOW) — resolved: the streaming reader no longer depends on the older whole-file reader — the shared transfer-syntax handling was moved into its own small helper (322eb9b).
  • ED-1 (MED) — resolved: reading deflate-compressed files now uses steady, bounded memory even when the bytes arrive faster than they are consumed. A test feeds a large compressed file slowly to prove memory stays flat (d8f3012).
  • ED-2 (MED) — resolved: the test suite no longer needs network access. The sample files it used to fetch are now bundled into the repository, and the few network-dependent tests are separated out, so a fresh checkout passes offline (442fc7d).
  • Default reader pivot (D28): the deferred, streaming (“lazy”) reader is deprecated and the standard whole-file (“eager”) reader is the default again (b9d8a9c), narrowing AD-3 from maintaining two default readers to a scheduled removal of one. (The section-2 diagram still labels the lazy reader the “default core,” which predates this change.)

Downstream validation: the event stream was exercised in a separate application — DicomEventStream.fromPart10(bytes).toNaturalized() produced the same naturalized metadata as the standard reader across the fixture set, and still recovered metadata from a malformed file that makes the standard reader throw. It now backs a real upload path there, protected by a test that checks the two readers agree.

8How to review this — suggested path

Ordered by the merge-risk argument in section 5: review the bottom of each dependency chain first. No single sitting is bigger than one idea. The umbrella PRs (#1/#2/#5/#6) are for browsing, not approving.

  1. Read the two plan documents first (CLAUDE_REFACTOR_PLAN.md, CLAUDE_REFACTOR_ANALYSIS.md). They are the web every PR hangs from — validating them validates the AI's context.
  2. Rewrite core, #21 → #27. Gate question per step: does the lazy core behave identically to the eager one? #27's three‑source equivalence matrix is the proof to spot‑check.
  3. Architecture review, #28 → #29. Check D16–D25 against your memory of Steve's actual comments; regenerate‑and‑diff the 76k generated lines rather than reading them.
  4. FHIR sink, #30. Small and self‑contained; verify mapping choices (MRN, UID identifiers, MADO) against your FHIR expectations.
  5. Streaming, #31 → #43. #31–#36 must be behavior‑neutral (suite unchanged); #37–#41 add one capability each; #42 is the formal gate — streaming ≡ buffered down to 1‑byte chunks.
  6. Evidence, #44 — and then the debt ledgers in section 6, which double as the post‑merge work plan.

9The decision skeleton

The repo carries its own reasoning: CLAUDE_REFACTOR_ANALYSIS.md records every design choice as question → options → decision → why. The fastest way to validate whether the AI captured sufficient context is to read the decisions, not the diffs. Highlights:

D0–D1
Decompose, contract first

"Refactor all of it" against ~40 pages of specs was split into slices A–G, dependency‑ordered. The event‑stream contract went first because every other slice is defined as its producer or consumer.

D2–D3
Push core, pull adapter, sync hot path

Push/callback is canonical with an async‑iterator on top; synchronous calls with async checkpoints keep the hot path allocation‑free while giving backpressure at element boundaries.

D4–D6
Binary, FMI, provenance

Encapsulated pixel data becomes a fragment sub‑stream; File Meta Information a bracketed leading sub‑stream; optional sourceSpan byte ranges give structural events provenance without obligating anyone.

D12
Loss preservation over policing

The stream emits every observed value regardless of declared VM; cardinality enforcement is a listener concern. This one rule is why three sources can naturalize identically (UC‑2).

D13–D14
Ergonomics without lying

Person Names get a proxy (.Alphabetic, string‑coercion to raw PN); numbers exceeding double precision keep their raw source string alongside the decoded value.

D15
Reuse the proven encoder

The Part 10 writer layers over canonical DicomDict.write rather than growing a second encoder (UC‑3) — and is the single deliberate import crossing in the dependency graph.

D16–D25
Steve Pieper's review, answered in writing

External review logged with drafted responses: byte‑identity guarantees, naming (events → dicomEventStream, materialize → naturalize), a validation layer, and proposed slices H (conformance) and I (dicom‑curate).

D22
One schema, three projections

The naturalized model's contract became machine‑readable: a normative rule catalog plus TypeScript and JSON‑Schema projections, generated from one source, held together by CI freshness‑and‑agreement gates (see ED‑5).

K7
Evidence‑based deferral

Re‑platforming AsyncDicomReader was assessed, two concrete breakage points documented (frame splitting, compressed‑frame assembly), and the work deferred to 1.x — a written "no" instead of a silent one (AD‑2).
